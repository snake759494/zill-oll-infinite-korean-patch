# 기술 설명

## 디스크와 아카이브
- DVD ISO(ISO9660 + UDF). 게임은 `cdrom0:\RES.RBB;1` 등을 파일명으로 연다.
- `RES.RBB` = Koei "RC ver2.1" 아카이브(32,900항목). 0x80부터 태그 구역 `RIDX`(오프셋, 크기|0x80000000=zlib) / `TYPE`(확장자) / `EXIX`(풀린 크기) / `GAP0`, 데이터 0x81000부터 0x80 정렬. `RES.RID` = CRC32(이름) → 항목 번호. 방 대사 이름은 `room/ID%04d/msgsec%03d_dat`, 공용은 `message/msgsec%03d`, `SHARE/StaiedMessage/msgsec%03d`.
- 압축은 zlib 1.1.3(게임 내장), 장면 로더는 연속된 항목들을 원본 오프셋 차이로 묶어 스트리밍 해제한다.

## 메시지
- 파일: `[u16 N][u16 오프셋×N][본문]`. 본문은 CP932 + 1바이트 가나(0xA1–0xDF, ESC H/K 모드), `0A` 줄바꿈, `05 05 05` 페이지 끝, `{01}I{02}x{04}` 조건 머리(변수 x, 비교, 숫자), `{02}x` 변수 삽입, `ESC C x` 색.
- 주인공 성별 = 변수 0x29. 머리 `0149022904 3d 25 30`(=0) 페이지가 남자, 다음 무머리 페이지가 여자.
- 메시지 버퍼 0xB69CEC(그룹0 [0,0x6800) / 그룹 165~167 [0x6800,0x8800) / 일반 0x8800~), 0xB83028 부터는 다른 게임 데이터.

## 글꼴
- `00012.frb` 안 `JillAll.fnt`: 유니코드 코드 레코드(24B: 코드, x0,y0,x1,y1, 폭) + 1024×1024 4bpp 텍스처(PSMCT32 폭 64 업로드 스위즐). 게임은 SJIS → 유니코드로 바꿔 레코드를 찾는다.
- 한글은 JIS 한자 SJIS 코드(889F~)에 배정하고 그 한자의 유니코드 레코드에 한글 글리프를 그린다. 반각 0x20 은 전각 폭으로 그려지므로 띄어쓰기는 폭 7px 전용 글자를 쓴다.

## 멈춤 방지 규칙 (build.py 자동 검사)
제작 중 세 번의 멈춤(메시지 버퍼 넘침 2건, 항목 배치 변경으로 장면 로딩 해제 실패 1건)을 겪은 뒤 정한 규칙:
0. **원본과 구조 동일**: RES.RBB 제자리 교체 — 모든 항목 오프셋·RBB 크기·RES.RID·ISO 레코드 그대로. 수정 항목은 풀린 크기 ≤ 원본(0 채움으로 같게), 압축 ≤ 원래 칸. 실행 코드 수정 없음.
1. 대사 파일에서만 1바이트 코드 0xA6~0xDD(0xB0 제외)를 자주 쓰는 음절 54자와 띄어쓰기에 배정(폰트의 히라가나 칸). 0xDE/0xDF(탁점) 금지. 이것으로 대사 파일이 원본 크기 이하가 된다.
2. 글꼴 글자 수 ≤ 원본(2,438) — 번역에 쓰인 음절 전부 + 남는 칸은 완성형 순. 알파 6단계.
3. 한 줄 문자열(이름 등)은 파일마다 한글판 최장 ≤ 원본 최장.
4. 조건 머리 뒤 반각 숫자는 조건값으로 읽히므로 전각 숫자로 자동 변환.
5. 실행파일 문자열은 제자리·원래 바이트 길이 이하.

## 그림 글자
MFZQ 텍스처(8bpp 스위즐, 팔레트 CSM1)의 글자 영역을 지우고 NanumSquare Neo ExtraBold 로 다시 그려 원본 팔레트로 양자화(`tools/tex_edit.py`, `tools/images.py`).
